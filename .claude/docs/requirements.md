# 要件定義書：AJOCCシクロクロス ラップタイム可視化アプリ

## 1. 背景・目的

開発者自身がAJOCCのE1カテゴリーで走る現役のシクロクロッサーであり、レース結果（[data.cyclocross.jp](https://data.cyclocross.jp)で公開されているCSV）を「自分ごと」として深掘りできる可視化ツールが存在しないという課題感から、個人開発で作成する。

## 2. 想定ユーザー・利用シーン

- **ユーザー**: AJOCC出場選手本人、およびそのサポート（同僚・チームメイト等）
- **シーン**: レース直後の会場、または帰りの車内で、スマホ（縦画面）でサクッと確認する
- **前提**: 詳細な分析ツールではなく、「自分と数人の比較」に特化した即答性の高いツール

## 3. 満たしたいデータニーズ

| #   | ニーズ                       | 概要                                               |
| --- | ---------------------------- | -------------------------------------------------- |
| 1   | 順位推移の可視化             | バンプチャート等でレース中のバトル発生を視覚化する |
| 2   | 特定ライバルとのタイム差推移 | 基準選手を±0秒としたギャップチャートで比較する     |
| 3   | ラップタイムのタレ具合       | オーバーペースや砂/泥区間でのミスを客観視する      |
| 4   | 昇格圏（トップ）とのペース差 | C2〜C4選手が次戦への目標値を把握する               |
| 5   | ワンタップ比較UI             | 自分を選択すると自動的に前後2〜3名が比較対象になる |

## 4. MVPスコープ（第一弾で外せない機能）

| #   | 機能                                           | 対応するニーズ | MVPでの割り切り                                                    |
| --- | ---------------------------------------------- | -------------- | ------------------------------------------------------------------ |
| ①   | 選手検索・選択（自動前後比較）                 | UX要件そのもの | 「前後」は最終順位ベースで固定。ラップごとの順位変動追従は次弾以降 |
| ②   | サマリーカード（現在順位／トップ差／昇格圏差） | ニーズ4        | 数値で即答することを優先し、グラフより先に配置する                 |
| ③   | ラップタイム推移チャート                       | ニーズ3        | 選択選手＋比較対象のみ表示。全選手重ね描きはしない                 |
| ④   | ギャップチャート（基準選手±0秒）               | ニーズ2        | 基準選手＝自分固定。比較対象の切替はタップのみ                     |
| ⑤   | 順位推移バンプチャート（簡易版）               | ニーズ1        | 比較対象内（自分＋前後2〜3名）のみに絞る。全体版は次弾             |

**設計方針**: 「全選手横断の分析ツール」ではなく「自分ともう数人のための比較ツール」に振り切る。

## 5. 開発フェーズ

| フェーズ  | 内容                                                                 | ゴール                                     |
| --------- | -------------------------------------------------------------------- | ------------------------------------------ |
| **MVP-0** | ダミーJSON（手動でCSVから1件変換）を用いて可視化UI（①〜⑤）を作り込む | 「見せ方」がUXとして成立するかを検証する   |
| **MVP-1** | データ収集・正規化スクリプトをGitHub Actionsで自動化する             | 運用の手間をなくし、実運用に耐える形にする |

MVP-0を優先し、可視化そのものの検証を先に行う。

## 6. データソースの制約（前提条件）

- 大会名選択: `https://data.cyclocross.jp/meet`
- レース結果: `https://data.cyclocross.jp/race/{race_id}`（race_idごとに1レース）
- 公式APIは存在せず、CSVダウンロードリンクからの取得が基本
- **CSVフォーマットが不統一**: 「各周回時点での累積経過時間」パターンと「各周回のラップタイムそのもの」パターンの2種類が混在しており、正規化処理が必要
- リザルトの発行タイミングが不定のため、一定間隔（目安10〜15分）でのポーリングが必要
- ブラウザから直接CSVを取得しようとするとCORS制約に抵触する可能性が高い

## 7. MVPの対象外（Out of Scope）

- 全選手を対象にした横断分析（順位表全体のバンプチャート等）
- ラップごとの動的な比較対象の再選出
- レース結果のリアルタイム性の完全な保証（数分〜15分程度のタイムラグは許容）
- 複数カテゴリー・複数大会をまたいだシーズン通算分析

## 8. 非機能要件

- 個人開発のため運用コストは可能な限り低く抑える（無料枠内での運用を志向）
- スマホ縦画面での表示を最優先し、PCレイアウトは考慮しない
