- 対象: <https://ajocc-laptime-viewer.vercel.app/>
- 実施日: 2026-09-02
- 対象リポジトリ: `01_ajocc-laptime-viewer`
- 方針: 公開サイトをデスクトップ・スマートフォン相当幅で実操作し、リポジトリの実装とデータも照合した。コード変更は行っていない。

- 大会一覧、シーズン・シリーズ絞り込み、大会遷移、カテゴリー切り替え
- 選手検索、選手選択、比較人数切り替え、全員表示、4種類のチャート
- 正常完走、DNF、少人数・多人数カテゴリー、外れ値を含むレース
- デスクトップ幅 2560×1215、モバイル幅 390×844
- 初期HTML、HTTPレスポンス、データ量、ビルド成果物、アクセシビリティ
- `npm run lint` と `npm run build`（ともに成功）

主な操作対象:

- `MMJ-256-005 / ME1`（8選手）、`ME2`（DNFを含む4選手）
- `KNS-256-010 / E1`（68選手、DNF 5人）、`E3`（38選手、DNF 1人）
- `CXK-256-004 / ME1`（約60選手）、`CK1`（20選手）、`WU15`（1選手）

データ全体は66大会、1シーズン、各大会6〜25カテゴリー（平均18.1カテゴリー）だった。

# 1. Executive Summary

1. 「大会を選ぶ → カテゴリーを選ぶ → 選手を選ぶ → 推移を見る」という核の流れは成立している。
2. 実データを幅広く収録し、順位・トップ差・ペース変化・ラップタイムを切り替えられる点は、競技経験者に明確な価値がある。
3. 一方、通常のリザルト表が存在せず、最も一般的な「順位と結果をすぐ確認する」目的を満たしにくい。公開プロダクトとして最大の欠落である。
4. 比較対象が最終順位の前後または全員に限られ、任意のライバルや知人同士を比較できない。
5. 68選手で「全員」を選ぶと、色の重複と凡例非表示により線の識別が事実上不可能になる。
6. DNF選手にも通常順位とトップ差が表示され、結果の意味を誤解させる可能性がある。
7. モバイルでは大会名が横スクロール内で切れ、主要ボタンの多くが25〜38pxと小さい。
8. カテゴリー略称、グラフ指標、「あなた」という基準選手表現は、観戦者や初心者への説明が不足している。
9. URLにフィルター・カテゴリー・選手・表示チャートが保存されず、共有・再訪・ブラウザバックに弱い。
10. 技術面では、全画面がクライアント取得のため初期HTMLに主要情報がなく、SEO、初速、エラー復旧、キャッシュに改善余地がある。
11. 欠損周回の突合を配列位置に依存する変換があり、データ条件次第で比較値が誤るリスクがある。
12. まずリザルト表、任意比較、DNF等の状態表現、モバイル一覧を整えるのが、コスト対効果の高い公開前改善である。

# 2. 良いところ

- 大会一覧が開催日降順で、日付・シリーズ・大会名の最低限の文脈が揃っている。
- シーズンとシリーズの絞り込みは即座に反映され、結果件数も把握しやすい。
- 大会ページでカテゴリー順を公式データに合わせており、現場の利用者が探しやすい。
- 選手検索と前後選手の比較は、少人数カテゴリーでは少ない操作で分析に入れる。
- 順位、トップ差、ペース、ラップという異なる問いをタブで分離しており、情報を同時に詰め込みすぎていない。
- ラップグラフで計測上の第1レコードを除外する設計は、実データの性質に合っている。
- モバイルでもページ全体の意図しない横はみ出しはなく、チャートのタップツールチップも動作した。
- DNFの文字表示、矢印ボタンの `aria-label`、`lang="ja"` など、アクセシビリティへの配慮が一部ある。
- 確認した操作ではコンソールエラーはなく、lint・production buildも成功した。
- 1人だけのカテゴリーでも破綻せず表示できる。

# 3. Critical Issues

## 3.1 通常のリザルト表がない

- **問題**: カテゴリーを選んでも、選手名、順位、タイム、所属、ステータスを一覧できず、先に選手を選ばないと情報に到達できない。
- **なぜ問題なのか**: レース結果サイトの最頻タスクは「誰が何位だったか」「自分の結果は何か」の確認であり、チャート分析より手前にある。
- **影響するユーザー**: 全ユーザー。特にスマホで結果だけ見たい人、応援者、初心者。
- **改善案**: カテゴリー選択直後にコンパクトなリザルト表を表示する。順位、選手、所属、公式タイム／トップ差、ステータスを基本列とし、行タップで分析対象にする。モバイルは順位・選手・結果を優先し、補助列は省略または詳細展開にする。
- **実装難易度**: Medium

## 3.2 任意の選手を比較できない

- **問題**: 比較は基準選手の最終順位前後 `±N` または「全員」に限定される（`hooks/useComparisonRiders.ts`）。
- **なぜ問題なのか**: 実際に比較したい相手は最終順位が近いとは限らず、スタート直後の競合、同チーム、年代別、友人などを選びたい。
- **影響するユーザー**: 選手、コーチ、レース展開を分析する人、複数選手の応援者。
- **改善案**: 基準選手とは別に、検索可能な複数選択UIを設ける。前後選手はクイックプリセットとして残し、任意選択と併用可能にする。選択上限は可読性を考え5〜8人程度にする。
- **実装難易度**: Medium

## 3.3 モバイルの大会一覧で大会名が読みにくい

- **問題**: 390px幅で一覧コンテナ343pxに対して内部幅749px、リンク幅672pxとなり、大会名が画面外へ切れる。`components/MeetSelector.tsx` の `overflow-x-auto` と `min-w-[42rem]` が原因。
- **なぜ問題なのか**: 横スクロール可能であることが視覚的に伝わりにくく、大会を特定する中心情報が隠れる。
- **影響するユーザー**: スマホ利用者全般。
- **改善案**: モバイルではカードまたは2段行に切り替え、日付・シリーズを補助情報、大会名を折り返し可能な主情報として表示する。横スクロールを前提にしない。
- **実装難易度**: Small

## 3.4 DNFを通常完走と同じ順位・トップ差で表現している

- **問題**: DNF選手を選ぶとボタンには `DNF` と出る一方、サマリーには「順位 4/4」「トップ差 +12'01"」と表示される。
- **なぜ問題なのか**: 順位が確定した完走者に見え、公式結果の意味を誤って伝える。型も `finished | dnf` のみで、DNS、DSQ、OTL等に拡張できない。
- **影響するユーザー**: 選手、応援者、結果を引用・共有する人。
- **改善案**: ステータスを第一級データとして表示し、DNF時は「DNF（最終通過4位／6周目まで）」のように区別する。トップ差も「離脱時点」など意味を明記する。DNS、DSQ、OTL等を扱える型へ拡張する。
- **実装難易度**: Medium

# 4. High Priority Improvements

## 4.1 多人数で「全員」表示が成立しない

68選手では折れ線が密集し、凡例がなく、6色のパレットが繰り返されるため個人を追えない（`lib/chartColors.ts`）。「全員」はリザルト表または順位分布に任せ、折れ線比較では選択上限を設ける。基準選手だけ太線、他選手を低彩度にし、ホバー／タップした系列を強調する。

**難易度**: Medium

## 4.2 選択状態がURLに保存されない

シリーズ絞り込み後に大会へ進みブラウザバックすると、絞り込みが解除され66大会に戻る。大会ページのカテゴリー、選手、比較対象、チャートタブも共有できない。クエリパラメータに状態を同期し、同じ分析画面を共有・再訪できるようにする。

**難易度**: Medium

## 4.3 初心者向けの説明が不足している

ME1、E1、CK1などの略称、トップ差・ペース変化の読み方、上位昇格ラインの意味が説明されない。カテゴリー名の補足、短い指標説明、ヘルプツールチップを追加する。「あなた」は観戦者には不適切なため「基準選手」または「注目選手」に変更する。

**難易度**: Small

## 4.4 検索の表記ゆれに弱い

`横山 航太` に対して `横山` は一致するが `横山航太` は一致しない。空白、全角・半角、大文字・小文字、可能なら読み仮名を正規化して検索する。所属名やゼッケンでも検索できると発見性が上がる。

**難易度**: Small

## 4.5 エラー画面が原因と復旧方法を示さない

存在しない大会URLでもHTTP 200で、汎用的な「時間をおいて再度」だけが表示され、一覧へ戻る導線がない。404、ネットワーク障害、データ破損を分け、「再試行」「大会一覧へ戻る」を提供する。再試行は同一URLへのリンクではなく実際の再取得にする。

**難易度**: Small〜Medium

## 4.6 カテゴリー変更時に比較モードが残る

「全員」を選んだまま別カテゴリーに切り替えると、そのカテゴリーでも全員表示になり、選手選択直後から大量の線が出る。カテゴリー変更時は比較を安全な初期値へ戻すか、引き継ぐことを明示する。

**難易度**: Small

# 7. Chart / Data Visualization Review

## 総合判断

現在の4指標は競技分析の問いを概ねカバーしているため、グラフ数を増やす必要はない。優先すべきは、比較相手の選択、系列識別、ステータス・欠損の正確な表現である。

| チャート | 判断 | 読み取れること | 主な問題 | 改善案 |
|---|---|---|---|---|
| 順位推移 | 残す・改善 | 各周で順位を上げた／落とした箇所 | 順序尺度に滑らかな `monotone` 曲線を使い、周回間に連続変化があったように見える。多人数で判別不能 | 直線またはステップ線。1位を上に固定。基準選手を強調し、終点に氏名／順位を直接表示 |
| トップ差 | 残す・改善 | 首位から離された／詰めた周回 | 欠損周回や周回遅れ時の意味が不明。配列位置での突合に誤対応リスク | `lapNumber` で結合。未計測は線を切る。周回遅れと時間差を区別し、単位を軸に常時表示 |
| ペース変化 | 表現を置き換える | 自分の基準ペースより速い／遅い周回 | 折れ線では正負の差と異常周回を瞬時に読みづらい。外れ値でスケールが潰れる | 0基準の発散型棒グラフを第一候補にする。速い／遅いを色と符号で明示し、平均との差または自己ベスト差のどちらかを明記 |
| ラップタイム | 残す・改善 | 周回ごとの絶対ペースと失速・回復 | 多人数・近似色・外れ値で読みにくい。線の補間が実測点以上の意味を持つ | 直線、選択系列強調、秒／分秒の明確化、外れ値注記、欠損点を接続しない |

### データ条件別の扱い

- **欠損データ**: 0や直前値で補完せず、点と線を欠損させる。ツールチップに「計測なし」と表示する。
- **周回遅れ**: 同一周回番号だけを比較し、終了後の欠損をDNFと混同しない。「-1 Lap」等の公式表記があれば優先する。
- **DNF/DNS/DSQ/OTL**: 線の終端にステータスを直接表示し、凡例・結果表でも一貫させる。
- **外れ値**: 削除せず、機材トラブル等の可能性を含む重要イベントとして注記する。例としてMMJ ME1では岡野選手の6周目714.1秒により順位が1位から7位へ変化した。
- **選手数増加**: 色だけに依存しない。5〜8人程度の表示上限、線種、直接ラベル、インタラクティブな強調を組み合わせる。
- **色**: 現行6色のうち白背景で3:1未満の色が複数ある。黄色・淡い緑・ピンクは線色として特に弱い。色覚多様性にも配慮したパレットへ変更する。
- **ツールチップ**: 選手、周回、値、順位／ステータスを同じ順序で表示し、キーボードでも同等情報へ到達できるようにする。

追加可視化を採用するなら、独立した新タブよりも既存グラフの表示モードとして「選択2選手間の差」を検討する。累積タイムはトップ差と重複が大きく、優先度は低い。

# 8. Mobile UX Review

- ページ全体の横スクロールは発生せず、チャートは画面幅に収まり、タップでツールチップも表示できた。
- 最大の問題は大会一覧の固定最小幅で、大会名を読むために横スクロールが必要になること。
- 比較ボタン約28px、タブ約25px、前後移動約32px、カテゴリー選択約38pxで、タッチ対象として小さい。原則44×44px前後を確保する。
- 25カテゴリーの選択肢は画面の大半を覆い、略称だけでは選びづらい。正式名称補足か検索を提供する。
- グラフ上で多数系列をタップ選択するのは困難。先に比較選手を選び、グラフは確認に集中させる。
- リザルト表は横スクロール前提にせず、順位・氏名・結果の3要素を一画面に収め、所属等は詳細展開する。
- 固定ヘッダーや操作領域を採用する場合は、チャート表示面積を圧迫しない高さに抑える。

# 9. Accessibility Review

## 良い点

- 文書言語が日本語に設定されている。
- 一部の前後移動ボタンに読み上げ用ラベルがある。
- DNFを色だけでなく文字でも表している。
- タップしたチャート値が `status` として公開される箇所がある。

## 問題と改善

- カテゴリー、シーズン、シリーズのラベルがフォーム要素と明示的に関連付いていない。`htmlFor` / `id` または `aria-labelledby` を設定する。
- 選手検索はプレースホルダーだけに依存している。常時表示ラベルを付ける。
- チャートSVGはフォーカス可能でもアクセシブル名と代替表がない。`aria-label`、要約、同値のデータテーブルを提供する。
- `text-flag` は背景に対して約3.31:1、`text-ink/55` は約3.94:1、`text-ink/40` は約2.53:1で、小さい本文には不十分な箇所がある。
- チャート色も青約4.42:1、橙約3.20:1、淡緑約2.82:1、黄約2.17:1、桃約2.69:1、濃緑約4.95:1で、複数が非テキスト要素の目安3:1を下回る。
- hoverだけでなくfocus-visibleでも選択・操作状態を明示し、タブ順で全操作を完結できるようにする。
- 選択状態を色だけで示さず、チェック、太線、テキスト等を併用する。
- 動きがある場合は `prefers-reduced-motion` に従う。

# 10. Technical Review

## コンポーネント・状態管理

- `RaceViewer` がカテゴリー、選手、比較、チャート表示とエラー境界を集約しており、機能追加時に責務が膨らみやすい。
- `hooks/useComparisonRiders.ts` の前後順位ベース設計がUI要件を固定している。任意選択とプリセットを分離した状態モデルが必要。
- 画面状態がローカルstateのみで、URL・履歴・共有と同期していない。
- カテゴリー変更時の状態リセットが部分的で、比較モードが意図せず残る（`components/RaceViewer.tsx`）。

## データ取得・キャッシュ・エラー

- `app/page.tsx` と `app/race/[meetId]/page.tsx` がClient Componentで、`useEffect` 経由でデータを取得するため、初期HTMLには大会名・レース名がなくスケルトンのみ。
- `hooks/useMeetData.ts` と `hooks/useRaceData.ts` にアプリ側のキャッシュ、重複排除、再検証、明示的リトライ戦略がない。
- `meets.json` は約118KB、確認したレースJSONは約88KB。raw GitHub側は `max-age=300` だが、クライアントごとに取得する設計である。
- 不正な大会IDがHTTP 200の汎用エラーになり、`not-found.tsx`、`error.tsx`、`loading.tsx` も用意されていない。
- `RaceViewer.tsx` の再試行導線は同一ルートへのリンクで、同じコンポーネント状態のまま確実に再取得する保証が弱い。
- Server ComponentまたはRoute Handlerで取得・検証・キャッシュし、404と一時障害を分ける構成が適する。

## 型安全性・データ変換

- 外部JSONをTypeScriptの型アサーションだけで受けており、ランタイムスキーマ検証がない。データ生成側の変更や不完全データで静かに誤表示する可能性がある。
- `lib/dataTransform.ts` のトップ差とペース差は、周回を `lapNumber` ではなく配列位置で合わせる箇所がある。途中周回が欠けた場合、異なる周回同士を比較する危険がある。
- 変換前にスキーマ検証し、すべての系列を `lapNumber` をキーに結合する。異常・欠損はUIに伝播できる識別可能な型にする。
- 結果ステータス型を `finished | dnf` から、実データに現れる状態を網羅する判別共用体へ拡張する。

## パフォーマンス

- 静的JSチャンク合計は約1.17MBで、Rechartsを含むチャンクは約414KB（minified、非圧縮）。選手未選択の段階でもチャートコードを読み込む。
- チャート領域を動的importし、選手選択後またはアイドル時に読み込むことで初期表示を軽くできる。
- 大会一覧は現状66件なら問題ないが、複数シーズン追加時は検索・ページングまたは仮想化を検討する。まずはサーバーフィルターよりUI検索で十分。
- 多数系列の再描画を避けるため、変換済み系列のメモ化、選択上限、安定したキーを徹底する。

## SEO・信頼性・保守性

- 有効なレースページの初期HTMLにもレース名がなく、タイトルも汎用。canonicalとOG情報も見当たらない。
- レースごとのmetadata、OG、公式ソース、更新日時を提供する。
- 自動テストがない。データ変換の単体テスト、状態遷移テスト、主要なモバイルE2Eを優先する。
- READMEが雛形に近く、データ仕様、ステータス定義、ローカル検証、デプロイ構成を保守者向けに記録する余地がある。

# 12. Recommended Roadmap

## Phase 1: 小さい変更で大きく改善

1. モバイル大会一覧を縦型レイアウトに変更する。
2. 「あなた」を「基準選手／注目選手」へ変更し、指標とカテゴリーの短い説明を追加する。
3. タップ領域、focus-visible、フォームラベル、低コントラスト色を修正する。
4. 選手検索を空白・全半角等で正規化する。
5. カテゴリー変更時の比較状態を安全にリセットする。
6. エラー種別、再試行、一覧へ戻る導線を整える。
7. 公式結果リンク、非公式表記、更新日時を表示する。

## Phase 2: 中規模改善

1. レスポンシブなリザルト表を導入し、行から分析へ遷移できるようにする。
2. 任意の比較選手を検索・複数選択できるようにする。
3. URLにフィルター、カテゴリー、選手、比較対象、タブを同期する。
4. チャートを直線／ステップ、直接ラベル、強調表示へ改善し、ペース差を発散型棒グラフにする。
5. DNF/DNS/DSQ/OTLと欠損・周回遅れを正確にモデル化する。
6. `lapNumber` 結合、ランタイムスキーマ検証、変換ロジックの単体テストを追加する。

## Phase 3: 新機能・大きな変更

1. サーバー取得・キャッシュ・metadata生成へ移行し、初速、SEO、信頼性を改善する。
2. 大会横断の選手検索と、最近見た選手／大会を導入する。
3. 比較リンク、画像／CSVエクスポートなど分析共有を追加する。
4. 実利用ログに基づき、2選手間の差など価値が確認できた分析モードだけを追加する。

## 結論

このアプリの強みは、実レースの周回データを4つの問いに分けて読み解けることにある。公開前に新しいグラフを増やすより、まず「通常の結果をすぐ見られる」「比較したい相手を選べる」「DNFや欠損を誤解なく読める」「スマホで大会名が見える」の4点を完成させるべきである。これにより、競技者向け分析ツールから、選手・観戦者・初心者が共通して使える結果閲覧プロダクトへ近づく。
