# AJOCCラップタイムビューア：データ可視化レビュー

レビュー日: 2026-09-03  
対象: [公開アプリ](https://ajocc-laptime-viewer.vercel.app/) とローカルリポジトリ  
範囲: 大会・カテゴリー選択後のデータ可視化のみ。大会検索など、可視化以外のUXは評価対象外とする。

## 結論

このアプリで最も価値が高いのは、順位そのものではなく「選んだ選手が、誰に対して、どの周で時間を得た／失ったか」を読めることにある。現行UIは選手を「あなた」として固定し、近い最終順位の選手を自動比較するため、分析を始めるまでの負担が小さい。この設計は残すべきである。

一方、現行4チャートはすべて複数選手の折れ線であり、「ギャップ」と「ペース」は同じ現象を累積値と1周差分で見せている。全員表示では線とツールチップが過密になり、色も6色で循環するため、選手識別が難しい。

採用するチャートは次の3種類を中核とし、4つ目は利用状況を見て追加するのがよい。

1. **タイム差推移**（現行ギャップを残し、最優先・初期表示にする）
2. **ラップタイム推移**（現行ラップを改善する）
3. **順位推移**（現行順位を改善し、補助表示にする）
4. **ペース／安定性プロフィール**（現行ペースと置き換える任意の追加チャート）

`cumulative time` の絶対値、`fastest lap`、`前周との差`、`平均lapとの差`をそれぞれ独立チャートにはしない。累積タイムはタイム差推移へ変換し、残り3つはラップチャートの注釈・ツールチップまたは要約値として統合する。

## 確認方法

公開環境を実際に操作し、次のケースを確認した。

- 2025-26もみじシクロクロス第5戦 / ME1
  - 1位選手を基準に±2名比較
  - 全8名表示
  - 順位、ギャップ、ペース、ラップの各タブ
  - 各チャートのホバー／タップによるツールチップ
- 第31回全日本選手権（日曜） / ME
  - 7位選手を基準に全15名表示
  - 順位とギャップの多人数表示
- デスクトップ幅と390 × 844pxのモバイル幅

ローカル実装では `RankBumpChart.tsx`、`GapChart.tsx`、`PaceChart.tsx`、`LapTimeChart.tsx`、比較対象選定とデータ変換処理を確認した。レビュー時のローカルHEADは `29d2dcd` である。公開環境とローカルHEADが同一デプロイであることまでは検証していないが、画面構成と挙動は一致していた。

## 3つの観点から見た総評

### UXデザイナーの観点

良い点は、最初に一人を選ぶだけで「あなた」を太線にし、前後の順位の選手を自動選択すること、選手を上下ボタンで切り替えられること、各タブに読み方の短い説明があることである。初見でも比較を開始しやすい。

改善余地は、タブ名が「ユーザーの問い」ではなく「指標名」になっていること、全員表示が選択可能でも分析可能な状態にならないこと、色と凡例への依存が強いことである。特にモバイルではツールチップがチャートの大半を覆い、全員表示では比較対象を追えない。

### データビジュアライゼーション専門家の観点

すべてのチャートでx軸を周回に統一している点はよい。タイム差の0基準線、選択選手の太線、順位軸の上下方向も適切な出発点である。

課題は、全選手を同じ強さのカテゴリ色で描くこと、6色を再利用すること、離散的な周回値を `monotone` 曲線で補間すること、全員ツールチップが未整理の長い一覧になることである。15名表示ではツールチップがグラフ中央を大きく隠し、同色の別選手も存在した。多人数時は「全員を別々の色で描く」のではなく、選択選手・固定比較選手・集団分布の3層に情報を圧縮すべきである。

### スポーツデータ分析者の観点

勝負を理解する中心指標は累積タイムそのものではなく、同じチェックポイントでの相対タイム差と、その差が各周でどう増減したかである。順位は重要だが、1秒差の順位変動と1分差の順位固定を区別できないため、単独ではレース内容を説明しない。

また「速かった」には、優勝した、単一周回の最速を出した、平均的に速かった、終盤まで速さを維持した、の異なる意味がある。これらを1つのランキングで混同せず、質問ごとに指標を分ける必要がある。

## ユーザーが本当に知りたいこと

| ユーザーの質問 | 判断に必要な情報 | 最適な表示 | 優先度 |
|---|---|---|---|
| 誰がレースを最も早く終えた？ | 最終順位・総合タイム | リザルト／要約値。チャート不要 | 高 |
| 誰が一番速い1周を記録した？ | 全選手の最小lap time | ラップチャートの最速マーカー＋要約値 | 中 |
| 誰が継続的に速かった？ | 平均lap timeとばらつき | ペース／安定性プロフィール | 中 |
| どこで勝負が決まった？ | 累積タイム差と1周ごとの差の増減 | タイム差推移 | 最優先 |
| 速い選手との差はどこで生まれた？ | 同じ周回での選手間累積差 | タイム差推移 | 最優先 |
| 誰が後半失速した？ | 前半と後半のlap time差 | ラップチャート、または安定性プロフィールの色 | 高 |
| 自分は誰と同じペースだった？ | 平均lap timeの近さとばらつき | ペース／安定性プロフィール | 中 |
| 自分はどの周回を改善すべき？ | 自分のlap time、前周差、平均差 | ラップチャートの注釈・ツールチップ | 高 |
| 順位が変わったのはどこ？ | 各周終了時の順位 | 順位推移 | 高 |
| 首位との差はどう変わった？ | 首位を基準とした累積タイム差 | タイム差推移の「首位基準」 | 高 |

### 「誰が一番速かった？」の扱い

この質問は曖昧なので、UI上では次の3つに分解する。

- **優勝者**: 最終順位1位。チャート外の要約値。
- **ファステストラップ**: 最小の有効lap time。ラップチャート上のマーカー。
- **最も高い持続ペース**: 有効周回の平均lap timeが最小。ペース／安定性プロフィール。

これにより「最速ラップを出したが勝っていない選手」や「突出した1周はないが安定して勝った選手」を正しく区別できる。

## 現在のチャート評価

### 1. 順位

**このチャートで判断できること**

- 各周終了時に何位だったか
- 何周目で順位を上げた／下げたか
- 選択選手と近い順位の選手がどう入れ替わったか

**判断できないこと**

- 順位差が1秒なのか1分なのか
- その周のどこで抜いたか
- 順位変動の原因がペース、転倒、機材トラブルのどれか

**評価**

レースの物語を短時間で把握する補助チャートとして有用である。現行の「上ほど順位が良い」、選択選手を太線にする設計はよい。一方、`monotone` 曲線は計測されていない周回間の順位を連続値として見せ、追い抜き地点まで推定できるように見える。全員表示では6色が循環し、同じ色の選手が複数いる。

**分類: 改善する。** 離散的なステップ線または直線に変更し、順位が変化した周だけ点を強調する。全員表示では他選手を薄い灰色に統一する。

### 2. ギャップ

現行実装は、選択選手の累積タイムを±0とし、比較選手の同じ周回時点の累積タイム差を描いている。

**このチャートで判断できること**

- 比較選手が自分より先行／遅れていたか
- 差が広がった、縮まった、維持された周回
- 最終順位だけでは分からない接戦や独走

**判断しにくいこと**

- 1周で何秒得た／失ったか。線の傾きから推測はできるが値は出ない
- 首位との差。首位が比較対象に入らない場合は見えない
- 全員表示時の個々の選手。線とツールチップが過密になる

**評価**

4チャート中で最も直接的に「どこで勝負が決まったか」へ答える。現在の説明文と0基準線も有効であり、基本概念はそのまま残す価値が高い。ただし「ギャップ」が誰を基準にするのかをタイトルだけで理解できず、符号の解釈にも説明文が必要である。

**分類: 残す。** 名称を「タイム差」にし、基準選手を明記する。ツールチップへ累積差とその周で得た／失った秒数を併記する。これにより現行ペースチャートの主要情報を吸収できる。

### 3. ペース

現行実装は、各周の `比較選手lap time - 選択選手lap time` を描く。プラスならその周は選択選手が速く、マイナスなら比較選手が速い。

**このチャートで判断できること**

- 特定の相手に対して、各周で何秒得た／失ったか
- ギャップが変化した直接の周回差

**判断できないこと**

- 自分自身のペースが安定していたか
- その周のlap timeの絶対値
- 自分の平均lapに対して速い／遅いか
- 別の基準選手を選んだときにも成立する、選手固有の「ペース」

**評価**

スポーツ分析上は意味のある差分だが、現行ギャップチャートの隣接周回差分であり、独立タブにするほど別の質問へ答えていない。「ペース」という名前から期待する自己の安定性ともずれている。0より上下する複数の線は、特に多人数で解釈負荷が高い。

**分類: 別チャートへ置き換える。** 1周差分はタイム差ツールチップへ統合し、このタブは選手ごとの平均ペースと安定性を比較する区間プロットへ置き換える。

### 4. ラップ

**このチャートで判断できること**

- lap numberとlap timeの関係
- 選手間のlap time絶対値の違い
- 前半／後半の上昇・下降傾向
- おおよその最速周回と、同じペースで走った選手

**判断しにくいこと**

- 正確なfastest lap。目視で最小点を探す必要がある
- 前周との差、本人平均との差
- 多人数時にどの線が誰か
- どの遅い周回が総合タイム差へ最も影響したか

**評価**

自己改善の中心となるチャートであり残すべきである。現在は絶対値だけを素直に示している点がよい。一方、重要な派生値をすべて目視計算させている。滑らかな曲線は周回間にも連続したlap timeがあるように見せるため、直線で十分である。

**分類: 改善する。** 選択選手の平均線、選択選手の最速周回、レース全体のfastest lapを注釈し、ツールチップに前周差・本人平均差・比較選手との差を追加する。

### 4分類のまとめ

| 分類 | 対象 | 判断 |
|---|---|---|
| 現在のチャートを残す | ギャップ | タイム差推移へ改名し、基準表記とtooltipを補強する。中心となる計算と0基準線は維持 |
| 現在のチャートを改善する | 順位、ラップ | 順位は離散表現と多人数強調、ラップは平均・fastest・差分の注釈を追加 |
| 別チャートへ置き換える | ペース | 1周差分をタイム差tooltipへ移し、任意の4つ目としてペース／安定性プロフィールへ置換 |
| 新しい表示を追加する | 要約表示 | fastest lapと選択選手の平均lapを追加。独立チャートにはしない |

## 指標ごとの採否

| 指標 | 採否 | 表示方法 |
|---|---|---|
| lap number vs lap time | 採用 | ラップタイム推移の主軸 |
| lap timeの絶対値 | 採用 | ラップタイム推移のy軸とツールチップ |
| 選手間のタイム差 | 採用 | タイム差推移 |
| 首位との差 | 採用 | タイム差推移の基準切り替え |
| cumulative time | 生値のチャートは不採用 | 同じ周回の累積差に変換して表示 |
| position transition | 採用 | 順位推移。ただし補助タブ |
| pace consistency | 採用候補 | 4つ目のペース／安定性プロフィール |
| fastest lap | 独立チャートは不採用 | 要約値＋ラップチャートのマーカー |
| 前周との差 | 独立チャートは不採用 | ラップ／タイム差ツールチップ |
| 平均lapとの差 | 独立チャートは不採用 | 選択選手の平均線＋ツールチップ |

`cumulative time` は全員の線がほぼ同じ右肩上がりになり、値の大半が「レースが進んだ」という既知情報になる。差を知りたい目的に対しては、累積値同士を引いたタイム差の方が情報密度が高い。

## 推奨する最終構成

### 1. タイム差推移（中核・初期表示）

| 設計項目 | 内容 |
|---|---|
| ユーザーが答えられる質問 | どこで勝負が決まったか、誰との差がどの周で生まれたか、首位との差がどう変化したか |
| x軸 | 周回番号。可能なら全員0秒の「スタート」を0として追加し、その後1、2、3…を表示 |
| y軸 | 基準選手に対する累積タイム差（秒）。上を「先行」、下を「遅れ」とし、±記号だけでなく語でも示す |
| 色の意味 | 基準線は濃い中立色、選択中の自分はオレンジ太線、固定した比較選手は識別可能な色、その他の集団は灰色または分布帯。色で速い／遅いを表さない |
| 選手選択方法 | 画面全体の主選手を「自分」とする。基準は「自分」「首位」「指定選手」から切り替え。比較は「近い順位」「似た平均ペース」「選手を追加」で最大4〜5名まで固定 |
| tooltip | 周回、基準に対する累積差、「この周で○秒得た／失った」、その周終了時の順位。値は基準からの先行／遅れ順に並べる |
| highlight | ホバー／タップした線以外を薄くし、縦ガイドを表示。選択選手が最も大きく得た周と失った周に小さな注釈を付ける |
| mobile | 高さ280〜320px。凡例の代わりに横スクロール可能な選手チップを上部に置く。タップ時の詳細はチャートを覆う浮動枠ではなく、チャート下の固定詳細欄に出す |
| 多人数選択時 | 個別色は最大5名。全員表示は全線を着色せず、集団の25〜75%帯＋範囲、選択選手、首位、固定比較選手だけを描く。ツールチップも選択選手と近傍3名に絞る |

計算式は `基準選手のcumulativeTimeSec - 表示選手のcumulativeTimeSec` とする。線の符号は「上ほど表示選手が先行」に統一し、UI上では `12秒先行` / `8秒遅れ` と書く。現行の符号を反転する場合、表示文言とテストを同時に変更する。

### 2. ラップタイム推移（中核）

| 設計項目 | 内容 |
|---|---|
| ユーザーが答えられる質問 | 後半に失速したか、同じペースだった相手は誰か、どの周を改善すべきか、fastest lapは誰か |
| x軸 | 周回番号 |
| y軸 | lap time絶対値（mm:ss）。数値として自然な「上ほど遅い、下ほど速い」を維持し、短い補助ラベルを付ける |
| 色の意味 | 自分はオレンジ太線、固定比較選手は最大4色、その他は灰色の中央値帯。本人平均は中立色の破線 |
| 選手選択方法 | 初期は自分＋最終順位の前後2名。追加候補として「平均lapが近い3名」を提示し、検索で固定できる |
| tooltip | lap time絶対値、前周との差、本人平均との差、基準選手との同周差、周回終了順位。DNFや記録終了は明記 |
| highlight | 自分のfastest lap、レース全体のfastest lap、自分の平均から最も遅い周を別形状で示す。色だけでなくアイコンとラベルを併用 |
| mobile | 10周程度までは全幅。点間隔が狭くなる場合は1周あたり最低32〜40pxを確保して横スクロールし、y軸を固定。詳細はチャート下へ表示 |
| 多人数選択時 | 線は自分＋固定4名まで。全員は線にせず、各周の集団中央値と25〜75%帯を背景表示する |

平均lapは「有効として表示した周回」の算術平均とする。現在と同様、最初の記録済み周回が複数周の合算値になるデータは除外する。平均の定義をツールチップまたはヘルプで明記する。

### 3. 順位推移（補助）

| 設計項目 | 内容 |
|---|---|
| ユーザーが答えられる質問 | 順位が変わったのは何周目か、誰と順位を入れ替えたか |
| x軸 | 周回番号 |
| y軸 | 周回終了時順位。1位を上にし、整数のみ表示 |
| 色の意味 | 自分はオレンジ太線、固定比較選手のみ色分け、その他は低彩度の灰色 |
| 選手選択方法 | 自分＋最終順位の前後2名を初期表示。検索で最大5名を固定。「全員」は文脈線として薄く重ねる |
| tooltip | 周回、順位、前周からの順位変化（2つ上昇など）、首位との差。並びはその周の順位順 |
| highlight | 順位が変化した周だけ点を表示。タップした選手の線を前面化し、他を薄くする |
| mobile | 高さ280px以上。y軸範囲は表示対象の順位範囲に少し余白を加える。線末端へ短い名前または順位ラベルを直接表示し、長い凡例を避ける |
| 多人数選択時 | 全員を異なる色にしない。自分と固定選手以外は灰色・低透明度・点なし。ツールチップは自分とその周の前後2名だけを基本表示し、「全員を見る」で展開 |

周回間は実測されていないため、曲線補間を使わない。周回終了時に順位が確定したことを示すステップ線が最も正直であり、難しければ直線＋実測点でもよい。

### 4. ペース／安定性プロフィール（任意の4つ目）

現行ペース折れ線の代わりに、選手ごとに1行を使う横向き区間プロットを採用する。平均lapの点とlap timeの四分位範囲を同時に示す。

| 設計項目 | 内容 |
|---|---|
| ユーザーが答えられる質問 | 誰が継続的に速かったか、自分と同じ平均ペースは誰か、誰が安定していたか、誰が後半失速したか |
| x軸 | lap time（mm:ss）。左ほど速い |
| y軸 | 選手。平均lap timeが速い順に並べる |
| 色の意味 | 前半平均に対する後半平均の差を連続色で表示。青緑＝後半改善、灰＝ほぼ一定、オレンジ＝後半失速。選手識別には色を使わない |
| 選手選択方法 | 有効データのある全選手を対象にし、自分の行を固定・強調。名前検索、上位20名、自分の近傍だけ、を切り替える |
| tooltip | 平均lap、fastest lap、四分位範囲、最大−最小、前半平均、後半平均、後半変化、記録周回数 |
| highlight | 自分の行を背景色と太枠で強調し、平均lapが最も近い3名にも淡い印を付ける |
| mobile | 1選手40px程度の縦リストとしてスクロール。選手名列を確保し、数値詳細はタップ後に行下へ展開 |
| 多人数選択時 | 1選手1行なので全員表示に適する。初期は自分の近傍または上位20名、検索で全員へ到達可能にする |

点を平均lap、太い横線を25〜75%範囲、細い横線を最速〜最遅とする。短い線ほど安定している。後半変化は `後半平均 - 前半平均` とし、プラスが失速である。これなら「平均が同じでも安定性が違う」を1画面で比較できる。

## チャート外に追加する要約表示

チャート数を増やさず、選手選択後の要約カードに次を追加すると、頻出質問へ即答できる。

- レースのfastest lap: 選手名、タイム、周回
- 自分のfastest lap
- 自分の平均lap
- 自分の最も大きくタイムを失った周: 比較基準と失った秒数

常時4項目すべてを大きく表示する必要はない。デスクトップは1行、モバイルは横スクロールまたは2列にし、詳細はチャート側へ委ねる。現在の順位・トップ差・昇格圏の要約と競合するため、初期実装では「fastest lap」と「平均lap」の2項目だけを追加するのが妥当である。

## 共通インタラクション設計

### 選手の役割を分ける

現在の「比較対象±N」は簡単でよいが、最終順位が近いこととペースが近いことは一致しない。次の3層に分ける。

1. **主選手**: ユーザーが分析したい一人。全チャート共通。
2. **固定比較選手**: 最大4名。検索、順位近傍、似た平均ペースから追加。
3. **集団**: 全員を個別色にせず、灰色線または分布帯で文脈として表示。

`±1`〜`±5`を並べる現在のコントロールは選択肢が細かすぎるため、「順位が近い」「似たペース」「全体」の3つのクイック選択と、個別追加へ整理できる。

### 色とラベル

- オレンジは主選手または最重要アクションに限定する。
- 固定比較選手は色覚多様性に配慮した最大4色を使い、線種または末端ラベルも併用する。
- 集団は灰色・低透明度にする。
- 同じ選手にはタブ間で同じ色を使うが、6色を超えて色を循環させない。
- hover/tap時は色を増やさず、太さ・透明度・背景でフォーカスを示す。

### ツールチップ

全選手の値を無条件に並べない。基本は主選手、固定比較選手、主選手に最も近い2〜3名だけを表示し、値でソートする。モバイルでは浮動ツールチップを避け、タップした周回の詳細をチャート直下の固定領域へ表示する。

## データ上の制約と誤読防止

- データは周回単位であり、セクターやコース位置を持たない。「どこで」は「何周目で」までしか言えない。
- `rankAtLap` は周回終了時の順位である。周回途中の正確な追い抜き地点は表現しない。
- ペース低下の原因はデータから分からない。転倒、パンク、渋滞などを断定しない。
- 周回遅れとDNFは、最後に同じ `lapNumber` が存在する地点まで比較し、その後の線を延長しない。
- 最初の記録済み周回が1周目ではない場合、現行実装と同様に最初のlap timeを単周回値として扱わない。
- 平均、fastest lap、四分位範囲の計算対象となる「有効周回」を全表示で共通化する。

## 現在の実装からの変更方針

### 既存データで実現可能か

`LapRecord` は `lapNumber`、`lapTimeSec`、`cumulativeTimeSec`、`rankAtLap` をすでに持っている。提案した4チャートと要約値は、原則としてビューア側の派生計算だけで実現でき、データ収集側のスキーマ変更は不要である。

ただし、セクター位置、転倒理由、正確な追い抜き時刻は現行データから作れないため、今回の設計範囲に含めない。

### 先に直すべき計算上のポイント

現行の `buildGapSeries` と `buildPaceDeltaSeries` は、基準選手の `lapNumber` を取りながら比較選手側を `rider.laps[i]` で参照している。すべての配列が同じ周回から同じ順序で始まる限り成立するが、欠損周回や異なる開始周回があると別の周回同士を比較する可能性がある。

変更時は必ず比較選手側も `lapNumber` で検索または事前に `Map<lapNumber, LapRecord>` 化する。DNF、周回遅れ、欠損データで線が正しく途切れることを確認する。

### 実装順序

予算と効果のバランスを考えると、次の順序がよい。

1. **低コスト・高効果**: タイム差を初期表示にし、現行ペースの1周差分をそのtooltipへ統合。順位の曲線補間をやめ、全員表示の色を灰色化する。
2. **自己分析を強化**: ラップに平均線、fastest lap、前周差、平均差を追加する。
3. **比較選択を改善**: 固定比較選手と「似た平均ペース」を追加し、全員表示を集団分布へ変更する。
4. **利用価値を確認して追加**: ペース／安定性プロフィールを実装する。利用頻度が低ければ3チャートのままにする。

第1・第2段階までで、主要な質問の大半に答えられる。4つ目を先に作る必要はない。

### 検証方針

現状の `package.json` には自動テストスクリプトがない。実装時は少なくともデータ変換を純粋関数として、次のケースを検証する。

- 通常完走者同士
- DNFと周回遅れ
- 欠損lap number
- 最初の記録が1周目ではないデータ
- 同タイムと0秒差
- 3名、8名、15名以上
- 3周、7周、10周以上

UIは390px、768px、1280px程度で、選手選択、基準切り替え、全員表示、タップtooltipを確認する。最終確認は `npm run lint` と `npm run build` に加え、公開相当データで代表レースを目視する。

## 最終提案

初回リリースでは、**タイム差・ラップタイム・順位の3チャート**に限定する。現行ペースの情報はタイム差ツールチップへ統合する。`fastest lap`、前周差、平均lap差はラップチャートと要約値へ入れ、独立タブを増やさない。

その後、「自分と同じペースの選手を探す」「安定性を全体比較する」という利用が実際に求められた場合だけ、4つ目として**ペース／安定性プロフィール**を追加する。この順序なら、最小の変更で最も重要な質問に答えつつ、全員分の多人数可視化も必要に応じて拡張できる。
