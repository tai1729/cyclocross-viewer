## 記録ルール

- 参加者IDだけを使用する。氏名、メールアドレス、電話番号、住所、
  勤務先、アカウント名、正確な生年月日などの直接識別情報は記録しない。
- 回答がなかった、答えたくない、または記録できなかった場合は `NR` とする。
  ファシリテーターが回答を推測して埋めない。
- 回答は可能な限り参加者本人の言葉をそのまま記録する。
- 「特になし」「分からない」「覚えていない」も有効な回答として記録する。
- 良い点を無理に探してもらわない。「特になければ『特になし』で構わない」と
  伝える。
- 質問は中立に読む。回答を肯定したり、正解を教えたり、改善案を誘導したりしない。
- 必須質問は全参加者に聞く。任意の掘り下げ質問は、テスト中の
  発言・行動・関心に応じて必要なものだけ聞く。
- これは主観回答の記録であり、回答だけでUXの良し悪しやプロダクト修正を確定しない。
  参加者記録の観察事実、他参加者との再現性、タスク結果と分けて分析する。

## 4. 任意の優先順位付け

順位付けを無理に求めない。答えられない場合は `NR` とする。順位は参加者の
好みを記録するためのものであり、所見の重大度や優先度ではない。

### 最も役立ったもの

1. 選手を中心にした周回チャート
2. 順位前後と固定選手の比較
3. 簡潔なリザルト表

### 最も分かりにくかったもの

1. 多人数比較時の参考線と選手名の対応
2. 「周回差」の意味
3. 選手名が操作対象であること

### 最も重要な改善

1. チャート上で各線と選手名を直接対応させる
2. 専門用語に短い説明を付ける
3. 選手名のクリック可能性を視覚的に強める

## 5. 任意の総合評価

数値は補助的な定量指標であり、これだけでUXの良し悪しを判断しない。自由回答、
操作観察、タスク成功、参加者間の再現性を主要な証拠として扱う。

| 項目 | 評価 | 任意コメント |
| --- | --- | --- |
| 分かりやすさ | 4 | 主要フローは明確。専門用語に推測が必要。 |
| 操作しやすさ | 4 | 大会・カテゴリー・指標切替は容易。選手名の操作性は弱い。 |
| 情報の見やすさ | 4 | 表は簡潔。長い結果表の末尾確認にはスクロールが必要。 |
| チャートの分かりやすさ | 3 | 注目選手は明確だが、多人数の参考線は判別しにくい。 |
| また使いたいと思うか | 4 | 自分や応援する選手のレース後分析に使いたい。 |

評価の意味: `1 = とても悪い`、`2 = 悪い`、`3 = どちらでもない`、`4 = 良い`、
`5 = とても良い`。

## 6. ファシリテーター専用まとめ

`Synthetic review interpretation — human facilitatorではない`

ここからは参加者回答の転記ではなく、ファシリテーターが回答後に記入する。参加者の
発言とファシリテーターの解釈を必ず分ける。解釈は仮説として扱い、
参加者記録の観察事実や他参加者の結果と混同しない。

| 項目 | 参加者の発言 — 引用または忠実な要約 | ファシリテーターの解釈 — 仮説のみ |
| --- | --- | --- |
| 最も強い肯定的反応 | 選手を選び、4指標と比較で周回推移を見られる点が便利 | リザルトと分析が連続することが価値として認識された可能性 |
| 最も強い否定的反応 | 6名比較では薄い参考線同士を識別しにくい | 比較人数増加時に凡例だけでは追跡負荷が高い可能性 |
| 主な混乱点 | 「周回差」を周回遅れ数と解釈した | 用語がリザルトの「-1周」と近く、一般ユーザーには区別しにくい可能性 |
| 主な改善要望 | 線の近くに選手名を表示するなど直接対応させる | 多人数比較の識別補助が必要な可能性 |
| 予想外のコメント | 「公式リザルトではありません」で正として何を見るか気になった | 注意書きは信頼性を補う一方、参照先の説明が必要な可能性 |
| 追加確認の候補 | 用語説明と線の直接ラベルが人間ユーザーにも有効か | Human Field Testで再現性を確認する |
| 過剰解釈しないためのメモ | Synthetic sessionの単一回答 | AI synthetic reviewであり、人間ユーザーでの再現性は未確認。Human participant countは0のまま。 |

### 証拠の扱いに関する注意

回答を所見へ昇格する場合は、参加者ID、質問番号、原文の引用、該当タスク、
参加者記録の観察事実、他参加者での再現数を紐付ける。回答1件だけで
プロダクトコード変更や重大度の確定を行わない。
