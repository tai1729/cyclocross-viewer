# シーズン・シリーズ・大会・カテゴリー選択機能 設計書

## 目的

現在のビューアは `race-27160.json` を固定取得している。これを、AJOCCの大会実績から生成した大会一覧を起点に、シーズンとシリーズで大会を絞り込み、大会選択後にカテゴリーを選んでリザルトを表示できる構成へ拡張する。

対象は2025-26シーズンを実データで検証し、将来シーズンも同じ収集処理で追加できるようにする。

## 採用方針

collectorがAJOCCの大会一覧・大会ページを取得して `meets.json` を生成し、viewerはGitHub Pages相当のraw URLから一覧と個別レースJSONを取得する。viewerからAJOCCへ直接アクセスしない。

カテゴリー名は正規化しない。大会ページのカテゴリータブの掲載順を大会ごとに保存し、関西の `E1` 系、関東の `ME1` 系などの表記差をそのまま表示する。

## データモデル

collectorで生成する `meets.json`:

```ts
interface MeetIndex {
  meetId: string;
  season: string;
  meetDate: string;
  series: string;
  meetName: string;
  categories: MeetCategory[];
}

interface MeetCategory {
  raceId: string;
  name: string;
  order: number;
}
```

`categories` は大会ページのカテゴリーリンクをDOM上の順番で保存する。`races.json` はcollectorの収集対象管理用として維持し、既存の `raceId`・`meetDate` に加えて必要なら大会識別子を持たせるが、viewerの一覧表示の正は `meets.json` とする。

個別の `data/race-{raceId}.json` と既存の `RaceResult` は、選択カテゴリーの表示に必要なため基本形を維持する。

## collectorの変更

### 大会発見

`discover.ts` は大会一覧から次のメタデータを抽出する。

- 大会識別子
- 開催日
- シリーズ名
- 大会名

大会詳細ページのカテゴリータブから、カテゴリー名と `raceId` を掲載順で抽出する。既存の `#cat_tab a[href*='/race/']` 抽出を利用し、リンクの順番を失わない。

発見結果は既存のレース情報とIDでマージし、重複大会・重複レースを作らない。取得に失敗した大会は警告を出し、成功した大会の結果は保存する。

### シーズン指定

現在の前後60日という発見範囲に加えて、シーズン単位の再発見を可能にする。CLIは次の形式を想定する。

```text
npm run discover -- --season 2025-26
```

シーズンの開始日・終了日はシーズン表記から決定し、対象期間内の大会を一覧から処理する。通常の定期実行は既存の近接日発見を使い、過去シーズンの初回投入や再構築ではシーズン指定を使う。

### 収集

`collect.ts` は `races.json` の対象を読み、未収集または開催日から一定期間内のレースを取得する既存仕様を維持する。25-26シーズンの初回投入では、シーズン発見後に全カテゴリーのレースJSONを生成する。

一部レースの取得に失敗しても、成功したJSONを保存し、処理全体は失敗件数を警告として出力する。

### GitHub Actions

既存の `discover → collect → commit` の順序を維持する。`meets.json` をcommit対象に追加する。過去シーズン投入は `workflow_dispatch` からシーズン指定を渡せる形を優先し、難しい場合は一度だけ手動でCLIを実行して生成物をcommitする。

## viewerの変更

### ルーティング

- `/`: 大会選択画面
- `/race/[meetId]`: リザルト可視化画面

ブラウザの戻る操作で大会選択画面へ戻れる。カテゴリーの選択状態はURLクエリに依存させず、画面内状態として扱う。初期カテゴリーは `categories[0]` とする。

### 大会選択画面

`meets.json` を取得し、開催日の降順で表示する。

- シーズン選択
- シリーズ選択
- 開催日
- シリーズ
- 大会名

シーズンを選ぶとシリーズ候補を該当データに限定し、シリーズを選ぶと大会一覧を限定する。未選択状態は全件表示とし、候補がない場合は空状態を表示する。

### リザルト可視化画面

大会IDから `meets.json` の大会情報を特定し、カテゴリーを掲載順で表示する。カテゴリー選択時に該当 `raceId` のJSONを取得し、既存の選手選択・比較対象・4種類のグラフを再利用する。

取得中はローディング、取得失敗時は大会名・カテゴリー名と再試行可能なエラー表示を出す。存在しない大会IDやカテゴリーIDの場合も、画面を壊さず大会一覧への導線を表示する。

## 25-26シーズンの検証

### データ検証

1. `discover --season 2025-26` で大会一覧を生成する。
2. `meets.json` に開催日、シリーズ、大会名、カテゴリー順が入ることを確認する。
3. `collect` でカテゴリーごとのレースJSONを生成する。
4. 大会数、カテゴリー数、JSON欠損数を確認する。
5. 既存の `race-27160.json` が壊れていないことを確認する。

### UI検証

1. `/` で大会が開催日降順になることを確認する。
2. シーズン `2025-26` の選択で対象大会だけになることを確認する。
3. 関西・関東などシリーズの切替で候補が変わることを確認する。
4. 大会を選択して `/race/[meetId]` に遷移することを確認する。
5. カテゴリーが大会ページ由来の順番で表示されることを確認する。
6. 別カテゴリーを選ぶと該当リザルトへ切り替わることを確認する。
7. モバイル幅とPC幅で大会表・カテゴリー選択・既存グラフが崩れないことを確認する。

### 自動検証

- collector: `npm run typecheck`
- viewer: `npm run lint`、`npm run build`
- JSONのスキーマ・重複・カテゴリー順の検証を可能な範囲でスクリプトまたは実行ログで確認する。

## 非対象

- カテゴリー名の全国共通正規化
- 大会の新規登録を行う管理画面
- AJOCCサイトへのviewerからの直接スクレイピング
- リザルトグラフ自体の仕様変更
